ynotPDF - MODULE CHECKLIST
==========================
Tick a box when the module is merged to main with CI green.
Start a module only when everything in its "needs" list is ticked.
Modules in the same wave can run at the same time (3-4 conversations).
Order is easiest-first, hardest-last: a usable app exists after wave 4,
the hard modules (text editing, redaction, signatures...) are waves 8-9.


Full plan: PLAN.md    Briefs: docs\modules\


HOW TO START A MODULE  (do exactly this every time)
----------------------------------------------------
1. Check the module's "needs" line. Every module named there must
   already be ticked [✔] below. If not, wait - do not start it.
2. Open a NEW Claude Code conversation.
3. Set its working folder to  D:\Projects\ynotPDF
   (in the app: choose the folder when creating the session, or run
   /cwd D:\Projects\ynotPDF  if you are already in one).
   The folder's CLAUDE.md then loads automatically.
4. Select the model shown on the module's "model:" line (/model in the
   conversation, or the model picker) BEFORE sending anything.
5. Paste the module's "prompt:" line below as the first message, exactly
   as written. Nothing else is needed - the .md file holds the full brief.
6. Run up to 3-4 modules from the SAME wave at once, one conversation
   each. Never two conversations on the same module.
7. When a conversation reports "merged to main, CI green", tick the
   module [✔] here AND check it shows as done in PLAN.md section 0.
8. If a conversation says a dependency is not finished, it will stop by
   itself - finish that dependency first, then re-run the prompt.

Special cases:
  M00 must run completely ALONE - nothing else until it is ticked.
  Before M00: create the private GitHub repo  tonybaynes/ynotPDF
  (empty, no README) and tell the M00 conversation it exists.
  M51 starts with a spike; its conversation may report back before
  building - answer its question, then let it continue.
