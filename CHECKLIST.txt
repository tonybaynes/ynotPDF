HOW TO START AND COMPLETE A MODULE
----------------------------------------------------
1. Finish reopened required scope first. New modules need completed dependencies.
   Bounded repairs can use already-merged dependency contracts while an unrelated
   part is reopened; explicitly record the boundary and revalidate integration.
2. Create one NEW task named "M<number> - <short description>" in an isolated
   worktree from current main. Never duplicate an active module owner.
3. Read CLAUDE.md, PLAN.md, the module brief and its dependency briefs. Use paths
   in that task's worktree; old absolute prompt paths below are historical.
4. Agree file ownership before parallel work. Same-wave modules are not
   automatically independent. The old model lines are historical suggestions;
   use the task's configured model unless Tony chooses another.
5. Implement, test through real UI journeys, update the brief/build log and
   commit coherent changes. Deferred required features keep the module open.
6. Push a PR. The coordinator serialises merges, reviews changes and verifies
   required CI on the proposed revision after integrating current main.
7. After all required module scope is complete and merged, the coordinator
   updates [✔] here AND PLAN.md section 0. Bounded partial merges stay unticked.
   Keep active repairs and remaining limitations visible here as work changes.
8. Remove only the finished task's own clean, merged worktree and local branch.
   Start its replacement only after completion and merge. Cap: ten tasks;
   current safe working capacity: four, with all local UI runs serialised.
